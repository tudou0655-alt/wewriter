# T-035 独立审核：83 分写法兜底提示词

状态：已对照设计、实际请求与实现独立复审；**提示工程的离线目标基本落实，客户文章质量和事实正确性尚未通过验收**。审核者只读代码，只维护本文件。

## 审核基准与边界

- 客户对《三篇对比稿-v2.md》给出整体 83 分。这是人工主观写法反馈，不是每篇的单独分数，也不是事实合格证明。
- 可提炼的写法：开头直接告诉特定读者“发生什么、为什么与自己有关”；小标题按读者问题和实际行动递进；将政策术语翻成业务判断；用具体、有出处的事实支撑建议。
- 不应继承的内容：三篇具体项目、金额、日期、政策、企业或机构名称、[S]/[W] 编号；未经核实的紧迫感、因果、传播和后果；固定“五条红线/四步自查/最后提醒”模板。样本的标题偏长、部分段落仍在说明核查过程，且稿件 11 有“四部门/七部门”待核事项，因此不得把它当作无缺陷金稿。
- 只做离线审查。样本、用户材料和网页均是资料而非指令；不读取密钥，不调用真实接口。

## 最终审核要逐项回答

1. 设计文件提出的行为，哪些确实进入**实际发送**的提示，哪些仅在文档或未使用常量中？
2. 代码改动是否只影响 T-035 范围，并保留 T-034 的标记修复、Claude 既有未提交实现及客户的干净导出要求？
3. 专项测试覆盖的是实际调用与边界，还是只断言字符串存在？全量测试是否实际跑完？
4. 哪些目标可离线证实，哪些必须用同一资料包的新旧匿名稿和客户打分确认？禁止把 83 分样本或模型自评分当作改进证据。

### 与设计逐项对照

| 项目 | 结论与证据 |
|---|---|
| 83 分样本兜底 | `wewriter/style.py` 的默认卡改为抽象的读者问题、事实解释与层级写法，不带遵义、马鞍山、具体样本项目或来源编号；`style_block()` 对有效的客户配置卡仍以配置卡替代默认卡。`tests/test_style_card.py` 用伪传输检查实际发送的 system 和 user，两种配置均覆盖。**这证明兜底进入请求，不证明模型能写出与样本同等质量。** |
| 读者主线、标题、开头、层级 | `wewriter/api.py` 的 `WRITER_RULES` 已写明一个读者判断、一条主线、可证实的标题钩子、前两三句讲清事实与关系、章节随证据变化，资料不足时缩减论点。`tests/test_style_card.py` 检查实际请求中包含这些规则，非仅检查未使用常量。尚无实际模型稿，标题吸引力与层级是否真的改善未验证。 |

### 必须保留的风险与建议

1. **P1｜自动采纳风格改写仍可能改变事实含义。** `wewriter/style.py` 的 `same_facts()` 比较数字、来源标记、标识和引号集合，不比较句义；`wewriter/api.py` 的 `basis_problem()` 主要检查编号与强措辞。我用虚构 F1/S1 “该项目可以申报”与改句“该项目不能申报。[S1]”重放，二者都没有报问题。本轮每篇新增审核，低于 4 分的稿件更有机会触发改写；提示词说“不改事实”及内部报告提醒不能代替验证。建议在进入客户自动交付前，至少将风格改写作为待人工确认的候选，或对改动句做独立事实复核并验证其有效性；未经验证不宣称改写后的事实已保持不变。
2. **P1｜“有理有据”仍未得到程序保证。** 编号存在可能与句子意思无关；写法审核输入不含原始证据，不能负责事实审核。标题和开头的“事实支撑”目前主要是模型遵循提示，离线测试只能证实提示已发送。还需在同一份已核实资料上核查真实稿件的逐句论述与来源关系。
3. **P2｜目标结构未做结果校验。** 写作同时输出 `outline` 与正文，`_finish_draft()` 只检查 `outline` 类型，未核对各小标题与主线的对应关系；小标题层级明晰仍待真实稿件和人工评价。不要把提示里的“每节一个问题”写成已实现的程序验收。
4. **P2｜调用、时延和成本上升。** 开启写法审核时，以前无规则命中的稿件现在每篇多一次模型请求；代码行为已证实，实际费用和等待时间尚无测量。建议真实对照时记录新增调用和耗时。
5. **既有范围外事实风险。** 正常联网稿仍被要求同时有 `[S]` 和 `[W]`，即使 W 与本文不相关；官方域名判定可将 `fake.gov.evil.example` 这样的虚构主机误判为 `official`（离线复现）。T-035 没有改这些代码，需在后续事实可靠性任务修复，不能归功于提示词优化。

**审核结论：** 对“写一个可执行的兜底提示词框架，并接入每篇写法审核”的离线实现，可进入人工查看阶段；对“文章已经达到客户 83 分、事实可靠且能稳定交付”的产品目标，**未通过**。需要真实模型前后对照、逐句事实核查、客户评分，并解决上述 P1 风险后再判定。

### 实现前已确认的事实正确性风险

用完全虚构的资料离线调用现有函数：事实 F1/S1 写“该项目可以申报”，待审句写“该项目不能申报。[S1]”并答依据 F1，`basis_problem(...)` 返回 `('', ['F1'])`；同样的两句交给 `same_facts(...)` 返回 `[]`。这证明两道**程序**检查没有完成语义蕴含校验，不能据此声称文章事实正确。新提示若提醒模型逐句核实，只能降低风险；除非另有可验证的语义核查与真实案例评估，本轮仍须把这项列为剩余风险。没有使用真实客户资料或接口。
