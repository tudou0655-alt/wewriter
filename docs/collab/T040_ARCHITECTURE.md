## 1. 一句话的目标结构

```text
界面（选择目标、请求次数上限、查看每篇结果）
  → 任务控制（冻结配置、阶段进度、付费前次数限制、重试）
  → 资料层（实时指标；正文/摘要；有出处与时效的研究）
  → 成稿层（初稿 → 事实审核 → 查证 → 风格审核 → 人工审核）
  → SQLite（阶段结果、费用事件、版本、证据）
```

保持现有单进程单任务锁；通过小型服务边界逐步提取逻辑。界面只读任务状态与调用业务命令，不复制预算和事实规则。提供 `TaskRun`、`CostPolicy`、`MaterialStore`、`DraftStage` 一类职责明确的接口即可，名称不构成硬性重命名要求。

## 2. 第一层：任务与费用控制

### 数据契约

每个任务保存冻结的模式、目标篇数、选文窗口、可选付费请求次数上限与价格表版本。费用事件至少能说明 `job_id`、阶段、供应商/模型、请求类别、发起时刻、状态（pending/measured/unknown）、输入/缓存/输出 token、搜索次数、估算人民币金额及估算依据。不得存密钥、请求正文、提示词、原始响应。父任务汇总子任务时按事件 ID 去重。

本轮可执行的控制采用可选的**付费请求次数上限**：未设置则沿用当前行为，设置后在每次可能付费的创建/调用请求前检查，并把父任务、子任务与 HTTP 重试合并计数。后台搜索结果轮询不算新的付费创建请求；一次搜索内的多次工具调用仍可能产生多笔费用，所以次数上限不能表述为金额上限。超时/断流的请求保留 `unknown` 与可能计费状态，请求次数照计；未经确认不自动重发同一付费工作。请求后用提供方 usage 结算估算，未知费用不得当 0。采集单价、汇率、模型价格均带日期与来源标记，费用面板只呈现本地估算。

`max_estimated_cny` 等人民币预算硬拦截属于后续目标：需先明确所有供应商价格、模型最大输出、搜索工具调用上界及保守预留策略，再决定金额阈值和未知价格的处理。当前无法在发起前可靠获知最终 token 与搜索工具次数，不能承诺人民币硬上限，也不能在界面使用“预算剩余金额”措辞。

调用路线：`Engine/设置页/补跑二审/其他付费入口 → Transport → RequestLimit.check() → CostMeter.begin() → provider → CostMeter.finish()`。原有 `CostMeter` 的费用事件可作为过渡期存储；统一接入点比在各个按钮分散计数更稳。若供应商一次搜索可发多个工具调用，须限制或预留其上界，才能进入未来人民币金额预算设计。

采集范围仍需覆盖客户要求的实时热度：每次任务重新读各账号的实时列表和指标。用户可选择较少账号、较小时间窗或目标篇数；界面在发起前说明账号数与估算请求范围。列表翻页与 HTTP 重试也应计入请求次数。不要用同日旧阅读量替代实时排行。

### 完成判据

虚构离线请求证明：未设上限保持原行为、设置上限时将超次数的付费请求挡在网络前、失败/超时保留可能计费且计数、重试累计原任务次数、批量父子任务合并计数、所有界面触发的模型调用都计入费用。未知价格仍标为未知，不当 0；没有真实账单时只报告代码与离线证据，不宣称节省比例。

## 3. 第二层：资料管理与复用

对数据分三类，不混用时效：

| 数据 | 复用条件 | 失效方式 |
|---|---|---|
| 阅读/点赞与账号列表 | 任务内可用；新任务实时再取 | 新任务开始 |
| 文章正文和分段摘要 | 原文内容哈希、处理规则版本、模型及参数相同 | 原文改变、用户清理、处理规则改变 |
| 联网研究及官方证据 | 同一政策/主题键，地区、文号、适用日期、来源与检索时间齐全 | 截止日或有效期过期、人工标记作废、关键来源改变 |

近期先沿用 `articles`、`analyses`、`research_cache` 既有结构，强化缓存键的内容指纹和版本、避免同任务重复处理。跨任务政策研究复用需要结构化时效及失效规则，建议后续独立迁移；只有标题相似或 URL 相同不足以证明研究可复用。文章来源关系和稿件版本的来源/报告快照，也作为后续独立迁移设计，保留旧库兼容及可回滚方案。

清理与备份作为数据契约：用户清理的正文和分析不得通过缓存复活；恢复时保持旧库可读；正式备份若需“完整资料”语义必须包含 SQLite 以外的文章图片及校验清单。现有 `Database.backup` 只复制 SQLite，界面应准确说明。来源链接、取得时间、适用范围和疑点随事实保留，供人工审核追溯。

### 完成判据

相同正文、相同模型与规则命中摘要缓存；原文或规则改变必失效；新任务仍触发实时指标；过期或缺关键元数据的研究不得自动采用；清理后缓存不可被读回。引入迁移前先做旧库恢复与备份往返测试。

## 4. 第三层：成稿与审核断点

阶段序列：`writing → fact_review → verification_if_needed → style_review → final_guard → saved → human_review`。每一阶段输出都应带任务/文章 ID、阶段名、输入指纹、模型与提示规则版本、完成时间、来源与质量状态。输出成功后持久化，再启动下一阶段；同一任务续跑只复用输入指纹一致且通过校验的阶段输出。新建采集任务不能复用旧任务的写作输出。阶段状态与最终人工审核状态分开表达。

在本轮不改数据库模式时，可通过现有 `analyses` 的缓存键按原文章 ID + job ID + 阶段/输入指纹保存过渡期输出，或使用现有可安全扩展的任务 JSON 字段。关键是先写成功结果、再标记可复用，并确保清理、恢复和异常退出语义一致；不能把未审核初稿保存成最终 `drafts` 记录后被 `Engine.run` 的“已有稿件”逻辑误判为完成。最终方案应由实现者以现有代码约束决定并测试。

事实安全：官方等级只能匹配核准的政府/采购域名边界，不能使用包含 `.gov.` 等子串的宽松规则。来源合法也不等于所述事实被来源支持。风格改写须至少保留句子中主体、动作、对象、金额、日期、地区、限制条件的绑定关系；静态检查无法确认时保留事实审核已通过的原句并提示人工复核。回退不应悄悄删除证据或改变来源标记。

### 完成判据

离线模拟在初稿、事实审核、联网查证、风格审核后分别中断；同任务续跑不重新支付已成功阶段，变更输入/模型/规则时不复用；完成稿与人工审核状态正确。虚构“甲乙金额互换”和伪政府域名必须被拒，相关反例写入回归测试。模型真实性仍需真实样本与人工复核，不能由离线静态测试单独证明。

## 5. 用户界面与观测

工作台在付费前显示目标篇数、实时采集账号数、可选付费请求次数上限、可能继续发生的研究和生成调用。运行中显示阶段、已用请求次数、剩余次数、已知费用估算、未知费用请求和停止原因。稿件卡同时展示产出篇数、事实二审、联网状态、未核实项、风格审核及人工审核状态。余额与费用估算分开，既有金币图可沿用。预设模式可配置“省钱/标准/精修”，但默认阈值及关闭哪些质量步骤必须经人工评估，不应由实现者臆定。

以“每篇人工审核通过稿件的总费用”为主指标，辅以采集候选利用率、摘要/研究缓存命中率、因失败重复付费率、生成耗时、事实缺陷、人工通过率。仪表板的分母和未知费用应可见；未记账历史不显示为 0。

## 6. 实施与复核顺序

1. **止损层**：域名判定与风格事实关系修复；补齐付费入口与请求次数限制；移除确无消费者的默认风格模型调用。只做离线虚构请求测试，不碰凭据或实际价格合同。
2. **续跑层**：阶段断点、输入指纹和清理语义；以中断/恢复测试证明不重写已完成初稿。只对当前任务有效，避免未经时效验证的跨任务研究复用。
3. **资料层**：先完善现有缓存键与统计；跨任务研究、完整版本关系和完整备份因需要 schema/格式变化，设计迁移与向后兼容验收后单独实施。
4. **界面层**：请求次数、费用估算和质量状态直接可见；虚构任务的五页 smoke 与人工实际 webview 验证，最终人工使用真实供应商账单和稿件质量样本做决定。

每一步由实现者交付具体 diff 与离线测试、独立复核者复跑关键测试并检查费用/数据/安全边界，主 agent 负责合并结论与未完成风险。业务调整不得承诺真实节省率；只有用户真实账单和人工通过稿件结果可以证明经济效果。
