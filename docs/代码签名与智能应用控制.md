# 代码签名与 Windows 智能应用控制

2026-10-26 客户在 Windows 11 上双击 `D:\微信插件\WeWriter.exe` 时被拦截，提示“智能应用控制已阻止可能不安全的应用……因为我们无法确认其编写人，并且它不是我们熟悉的应用”。本文说明原因、长期方案、构建脚本里已经落实的部分，以及给客户的临时说明。

## 1. 原因

智能应用控制（Smart App Control，下称 SAC）是 Windows 11 22H2 起在全新安装的系统上默认开启的保护。每次运行程序（包括程序加载的 DLL）时，它按下面的顺序判断：

1. 微软云端信誉：这个文件是否被大量用户安全使用过。WeWriter 每次构建都是新文件、新哈希，安装量极小，所以永远没有信誉。
2. 数字签名：文件是否带有受信任证书颁发机构签发的有效代码签名。当前 WeWriter.exe **没有任何签名**，提示里“无法确认其编写人”指的就是这个。
3. 两者都不满足就直接阻止。

和 SmartScreen 的“仍要运行”不同，SAC **没有“仍要运行”按钮，也不能把单个程序加入白名单**。所以“右键属性→解除锁定”、“以管理员身份运行”、换目录通常都没用。

还有一个容易忽略的点：WeWriter 是 PyInstaller 单文件程序，运行时会把 Python 扩展（`.pyd`）和 DLL 解压到临时目录再加载。SAC 对这些 DLL 同样做检查，所以**只签 WeWriter.exe 不够**，里面未签名的 DLL 也要签。

## 2. 长期方案（需要人工决定和采购）

根本解决办法是给程序做代码签名。二选一：

| 方案 | 适合谁 | 费用（大致，以官网为准） | 说明 |
|---|---|---|---|
| Azure Trusted Signing（微软托管签名，现在也叫 Artifact Signing） | 位于美国、加拿大、欧盟、英国的公司；美国、加拿大的个人 | 基础版约 9.99 美元/月 | 微软替你保管密钥，适合自动化构建。**中国大陆的个人或公司目前大概率不符合申请条件**，需要先在 Azure 门户确认资格 |
| 向受信任 CA 购买 OV 代码签名证书（DigiCert、Sectigo、GlobalSign、SSL.com、Certum 等，国内可通过代理商购买） | 有营业执照的公司；部分 CA（如 Certum）也给个人发证书 | 约每年一千到几千元人民币 | 自 2023 年 6 月起，私钥必须保存在 USB 硬件令牌或云 HSM 里，签名时需要插着令牌或登录云服务 |

补充说明：

- 对 SAC 来说，**普通 OV 证书的有效签名就够了**，不必买更贵的 EV 证书（2024 年起 EV 也不再自动消除 SmartScreen 提示）。
- 签名后，浏览器下载时的 SmartScreen 提示可能还会出现一段时间，直到积累信誉；这和 SAC 拦截是两回事，不影响客户运行。
- 证书上的公司/个人名称会显示为“发布者”。构建时把 `WEWRITER_PUBLISHER` 设为同一个名称，文件属性里的公司名就会一致。
- 资料来源：[Artifact Signing（原 Trusted Signing）](https://azure.microsoft.com/products/artifact-signing)、[微软代码签名选项](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)、[2026 年 4 月更新允许无需重装重新开启 SAC](https://www.anoopcnair.com/windows-11-april-2026-update-smart-app-control/)。资格与价格会变，采购前以官网为准。
- 其他可选路线：上架 Microsoft Store（Store 会替应用签名，SAC 信任 Store 应用），但需要改成 MSIX 打包并验证内置浏览器能否正常工作，工作量较大；把每个版本提交给微软人工审核（https://www.microsoft.com/wdsi/filesubmission）速度慢、每个版本都要重新提交，不推荐作为主要方案。

## 3. 构建脚本里已经落实的部分

| 文件 | 改动 |
|---|---|
| `scripts/sign.ps1`（新） | 用 signtool 做 Authenticode 签名并逐个校验。支持两种方式：Azure Trusted Signing（`WEWRITER_TS_DLIB` + `WEWRITER_TS_METADATA`，先 `az login`），或证书库里的证书（`WEWRITER_SIGN_THUMBPRINT`，适用于 USB 令牌/云 HSM）。`-OnlyUnsigned` 会跳过已经有有效签名的文件（如 python313.dll、微软运行库、node.exe）。仓库里不存放任何密钥 |
| `scripts/build.ps1` | 新增 `-Sign` 开关：先检查签名配置，再让 PyInstaller 打包前签名所有内置 DLL/.pyd，最后签名 `WeWriter.exe`。`signtool` 不支持普通 PowerShell 源文件，因此可选的 `install.ps1` 不纳入这条签名链；客户可直接运行已签名 EXE。不加 `-Sign` 时照常构建，但会醒目警告“未签名，客户电脑上会被智能应用控制拦截” |
| `scripts/build_to_desktop.cmd` | 检测到上面任一签名环境变量时自动加 `-Sign` |
| `WeWriter.spec` | 关闭 UPX 压缩（UPX 压缩的程序容易被安全软件误报）；加入文件版本信息（产品名、版本号、发布者）；`WEWRITER_SIGN=1` 时在打包前把未签名的内置二进制复制到 `build/signed-binaries/` 签名后再打包 |

拿到证书后的构建步骤（以 USB 令牌证书为例）：

```powershell
# 1. 安装 Windows SDK 的“Signing Tools for Desktop Apps”（提供 signtool.exe）
# 2. 插入令牌，在“certmgr.msc → 个人 → 证书”里找到代码签名证书，复制它的指纹（Thumbprint）
$env:WEWRITER_SIGN_THUMBPRINT = '证书指纹'
$env:WEWRITER_PUBLISHER = '证书上的公司或个人名称'
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Sign
# 3. 检查：右键 dist\vX.Y.Z\WeWriter.exe → 属性 → “数字签名”选项卡应显示签名者且“此数字签名正常”
```

使用 Azure Trusted Signing 时，把第 2 步换成：安装 Trusted Signing Client Tools，`az login` 登录，写好 `metadata.json`（Endpoint、CodeSigningAccountName、CertificateProfileName），再设置 `WEWRITER_TS_DLIB`、`WEWRITER_TS_METADATA` 两个环境变量。

尚未验证：这些脚本是在没有 Windows 和证书的环境里写的，还没有真实签名跑过一次。拿到证书后第一次构建，请把 `build.ps1 -Sign` 的完整输出发回来核对。

后续建议（未做，涉及交付形态变化）：改为 PyInstaller 文件夹模式（onedir）加签名安装包（如 Inno Setup）。这样不再每次启动解压到临时目录，启动更快，也更少触发安全软件。

## 4. 给客户的临时说明（可直接转发）

> 您好，WeWriter 被 Windows 11 的“智能应用控制”拦截，是因为当前版本还没有做数字签名，系统无法确认发布者，并不是检测到了病毒。这个功能没有“仍要运行”的选项，也不能单独放行某个程序。
>
> 我们正在为软件申请数字签名，签名版发布后直接双击就能运行，不需要改系统设置。
>
> 如果您现在就需要使用，可以关闭智能应用控制：打开“设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 智能应用控制设置”，选择“关闭”。关闭后 Microsoft Defender 杀毒等其他防护照常工作。需要提醒的是：已安装 2026 年 4 月及以后更新的 Windows 11 可以随时在同一位置重新打开（重新打开后未签名的 WeWriter 会再次被拦截）；更早的版本关闭后**无法再重新打开**，只能重置系统才能恢复。如果您介意这一点，请等待签名版。
