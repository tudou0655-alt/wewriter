# T-035 三 agent 协作与文件所有权

本任务按人工要求由三个子 agent 协作，Codex 主 agent 负责登记、协调、整合证据及最终交接。三个职责可以同时开始，但实现必须以设计结论为依据，最终审核必须检查实际实现；并行不等于跳过依赖。

| 子 agent | 职责 | 可编辑文件 | 交付 |
|---|---|---|---|
| 1 框架设计 | 阅读 83 分样本和实际调用链；提炼可复用的标题、开头、层级、证据与风格优先级；给出最小修改方案和反例 | `docs/collab/T035_PROMPT_DESIGN.md`（新建） | 设计、实际提示结构、验收样例，不改程序 |
| 2 实现 | 先检查已有未提交改动；等待并使用 agent 1 的设计结论；局部修改提示和必需测试，避免采集/数据库/UI 重构 | `wewriter/api.py`、`wewriter/style.py`、`wewriter/pipeline/composition.py`、`tests/test_article_quality.py`、`tests/test_readability.py`、`tests/test_style_card.py`、`docs/collab/T035_IMPLEMENTATION.md`（新建）；未用到的文件不改 | 代码、专项测试、实际调用内容证据；保留 T-034 修复 |
| 3 独立审核 | 先独立提出针对目标的审核清单；实现完成后对照设计、代码与离线测试审查，指出未达标处 | `docs/collab/T035_PROMPT_REVIEW.md`（新建） | 分清已证实、未证实与推测；不改实现文件 |
| 主 agent | 协调、解决冲突、补做必要验证、汇报 | `docs/collab/T035_GOAL.md`、`docs/collab/T035_COLLAB.md`、`docs/collab/TASKS.md`、`docs/collab/HANDOFF.md` | 最终状态、验证证据、剩余风险 |

## 工作顺序

1. 三人并行开始：设计者定框架；实现者先只读检查现有提示与测试，待设计文件可用再动代码；审核者先独立制定评价清单。
2. 实现者对设计逐项落地、做离线测试并记录实际发送的 system/user 内容。事实与风格的边界优先于模仿样本；如设计与现有用户禁令冲突，停止该项并报告。
3. 审核者在实现完成后做真正的差异审核；主 agent 根据问题决定修复或如实记录阻塞，不把自评当客户验收。

## 共同安全边界

不调用付费模型或真实网络接口，不读取密钥，不更改依赖、数据库与 UI，不打包、不提交、不推送。保持客户发布稿干净、内部来源对应关系可追溯。现存未提交修改由原作者所有；只在本表分配的文件内做最小编辑，遇到同文件正在被其他工作者编辑时先暂停并报告。
