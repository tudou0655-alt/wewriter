# T-035 实现记录（子 agent 2，2026-10-27）

依据 `T035_PROMPT_DESIGN.md` 局部修改。代码在当前未提交工作区上原位编辑，未覆盖 Claude 先前的修改或 T-034 句末 `[W]` 修复；未调用真实采集、搜索或写作模型，未读凭据、安装依赖、修改数据库/UI、打包、提交或推送。客户 83 分是写法基准，不是新稿评分。

## 文件和行为

- `wewriter/style.py`：重写无客户配置时的默认风格卡。标题聚焦一个有据的读者利益，开头解释事实和读者关系，章节随证据而变；删去固定清单、强制紧迫感和样本选题。正面示例只作给定虚构事实的同义改写，不额外加入凭证、惩罚或期限。已有客户风格卡仍替代默认卡。
- `wewriter/api.py`：写作 system 在事实规则之外增加读者判断/主线、标题和开头、层级与资料不足时缩短的指示；`user_style` 与已配置卡的关系统一为事实边界 > 客户明确写法 > 已配置卡/范文 > 兜底卡。旧 `style_reference` 名称不再在共享优先级中出现。写法审核明确每篇看标题、前两三句、层级和自然度；核心四维不足 4 分或其他维度不足 3 分才请求改写。**写法审核的 user 输入没有原始证据，只能评估稿内表达，不能核实事实**；system 已明确告知模型此边界。来源编号须与句义匹配的要求已写进写作提示，但这仍是模型指示，不是程序验证。
- `wewriter/pipeline/composition.py`：设置启用写法审核时，即使确定性 `readability_problems` 没有命中，也执行一次已有的 `style_review`；关闭开关或不支持时不调用。程序按照维度门槛决定是否采纳改写，缺少有效改写时保留上一版并提示人工。对通过静态检查的改写，记录“语义仍需人工复核”，不再声称事实已被证明不变。
- `tests/test_style_card.py`、`tests/test_readability.py`：离线伪传输核对**实际发送**的 system/user；分别测试无配置兜底、有配置覆盖、无可读性信号仍审核、关闭开关不调用、核心 3 分需改写和达标时不采纳无谓改写。保留 T-034 句末 `[W]` 回归测试。

## 调用次数和边界

写作、事实二审的调用入口与次数未改。**写法审核开启时，每篇新增保证的一次审核调用**：以前可读性规则未命中的稿件会跳过，这些稿件现在增加 1 次模型调用、相应耗时和费用；已会触发审核的稿件次数不变。是否产生改写仍取决于审核结果；本轮未运行任何付费调用，不能给实际费用或速度数字。

`same_facts()` 仍只比较数字、来源编号、标识和引号内容，不能识别“可以申报”改为“不能申报”等含义反转。现有 `basis_problem()` 也主要校验依据编号和部分说法强度，无法补足语义验证。此处未新增复杂审核链；采用写法改写仍需人工事实复核，不可宣称程序保证论述正确。独立的强制 `[S]+[W]`、官方域名等级误判也不在本轮提示词修改范围内。

低分且模型没有返回有效改写、或改写没有通过静态校验时，流程仍保留上一版稿件并把原因写进内部风格报告，**不会把该稿自动判定为客户质量门槛已通过**。本轮保证的是“开启开关时每篇接受一次写法审核”，不是“每篇达标”。
