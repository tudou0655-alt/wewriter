# 交付验收清单

适用版本：WeWriter 0.10.3 及之后。本清单区分三类证据，未执行的项目一律不得记为“通过”。

| 标记 | 含义 |
|---|---|
| 【自动】 | 在开发机上用命令即可得到确定结果，不联网、不需要真实账号 |
| 【人工】 | 需要人在目标 Windows 环境中操作并观察 |
| 【外部】 | 需要真实 API Key、微信读书账号或代码签名证书等外部资源 |

每次交付在“结果”列填写：通过 / 失败 / 未执行，并附日期、执行人和命令输出或截图位置。

## 1. 自动化检查（开发机）

| # | 检查 | 命令 | 通过标准 | 结果 |
|---|---|---|---|---|
| A1 | 离线交付检查 | `.\.venv\Scripts\python.exe scripts\verify_delivery.py` | 退出码 0，输出“0 项失败”。检查 Python 版本、必需文件、版本号一致、锁定依赖、模块导入、演示库初始化/备份/恢复/迁移 | |
| A2 | 全量单元测试 | `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` | 末行 `OK`，测试数不少于上次交付 | |
| A3 | 专项测试 | `.\.venv\Scripts\python.exe -m unittest tests.test_db_migrations tests.test_startup tests.test_delivery tests.test_logs -v` | `OK` | |
| A4 | 工作区干净 | `git status --short`、`git diff --check` | 无未提交改动、无空白错误 | |

A1–A4 只证明代码在开发机上的确定性行为，不代表客户机器、真实 API 或登录流程可用。

## 2. 演示与打包（开发机，需要图形界面）

| # | 检查 | 命令/操作 | 通过标准 | 结果 |
|---|---|---|---|---|
| B1 | 演示 smoke | `.\.venv\Scripts\python.exe main.py --demo --data-dir .local-data\delivery-demo --smoke-test .local-data\delivery-smoke.json` | 窗口自动关闭，`delivery-smoke.json` 中 `"ok": true` 且 6 个页面全部列出 | 【人工】确认 |

| B3 | 打包产物启动 | 双击 `dist\v<版本>\WeWriter.exe`（建议加 `--demo`） | 主界面正常显示，无报错弹窗 | 【人工】 |

## 3. 目标环境人工验收（客户干净 Windows 机器）

| # | 检查 | 操作 | 通过标准 | 结果 |
|---|---|---|---|---|
| C1 | 安装 | 解压 zip，运行 `install.ps1`（无需管理员权限） | 开始菜单/桌面快捷方式可启动 | 【人工】 |
| C2 | 首次启动 | 启动软件 | 正常进入主界面；数据目录在 `%LOCALAPPDATA%\WeWriter` | 【人工】 |
| C3 | 数据库异常提示 | 用一个比当前版本新的数据库或损坏的数据库启动（使用测试数据，不要用客户真实数据） | 弹出中文提示，不显示路径或技术堆栈，软件退出而不是进入半初始化界面 | 【人工】 |
| C4 | 备份与恢复 | 设置页备份，再恢复该备份 | 数据一致，定时任务被暂停；恢复失败时原数据保持可用 | 【人工】 |
| C5 | 计划任务与休眠唤醒 | 开启定时任务，让机器休眠后唤醒 | 唤醒后按计划执行或正确补跑，日志无未捕获异常 | 【人工】 |
| C6 | 托盘与最小化 | `--minimized` 启动、关闭到托盘、单实例 | 行为符合说明，不出现第二个实例 | 【人工】 |
