# 公众号工作台 · Windows 试用版 v0.10.2

本地管理公众号，通过微信读书扫码登录采集文章，使用 OpenAI / DeepSeek 联网研究并分别生成 2–3 篇不同主题的稿件。客户不需要安装 Python 或数据库服务。EveryInfra 获取评论，由所选摘要模型提炼读者关注点。

## 客户使用

1. 解压 `WeWriter-Windows.zip`，双击 `WeWriter.exe` 即可运行。也可以右键 `install.ps1`，选择使用 PowerShell 运行，将软件复制到当前用户的程序目录并创建桌面快捷方式。组织策略限制脚本时，直接运行 EXE。
2. 在手机微信读书 App 中把目标公众号加入书架，并在“我 → 设置 → 微信读书 Skill”获取 API Key；把 Key 填入软件“设置 → 模型与联网”的“微信读书 Skill Key”。
3. 软件“公众号管理”点击“Edge 扫码登录”，在自动打开的专用 Edge 窗口中使用同一微信账号扫码确认。登录成功后再点击“同步公众号”。标识自动填写，可在软件中增删、启停。旧配置中名称完全相同且唯一的账号会更新标识，停用状态保留；未同步的旧账号需加入书架或停用。
4. 在“设置”填写 OpenAI、DeepSeek 和 EveryInfra 的 API Key，保存。联网研究必须配置 OpenAI Key；摘要和写作可选择 OpenAI 或 DeepSeek；评论功能使用 EveryInfra Key。
5. OpenAI 默认使用官方 Responses API，模型为 gpt-5-mini，可填写账户支持的其他模型 ID；联网模型须支持 web_search。DeepSeek 默认使用官方接口，模型 ID 为 `deepseek-flash`。
6. “测试采集”会验证最新一篇文章正文，不调用生成模型；模型测试按供应商规则计费。微信读书登录失效后重新扫码。
7. 回到“概览”，点击“立即采集并生成”。在“运行记录”查看进度与错误，在“稿件工作台”编辑、审核及导出。
8. 确认手动运行正常后，启用每日定时，并按需要开启“登录 Windows 时启动软件”。关闭窗口选择“是”，软件继续在托盘运行。

默认：最近 24 小时，单账号最多查询 24 篇，按阅读量选择前 3 篇尚未使用的文章，各生成一篇约 1500 字的独立稿件；可改为 2 篇。仅代表管理的公众号及查询范围，不是全网榜单。

## 每篇独立联网写作

每篇文章单独提取重点和证据、分析自身风格，再用 OpenAI web_search查找相关补充资料，由所选模型独立写作，不跨主题合稿。公众号来源标为 [S数字]，联网来源标为 [W数字]，导出文件附链接。搜索必须返回带引用的来源；无来源时停止该篇，不以模型记忆冒充搜索。模型整理的网络资料仍需人工审核。

联网使用 OpenAI Responses 接口，与写作模型独立配置。即使写作选择 DeepSeek，也需要 OpenAI Key 来联网检索。搜索、评论与模型调用均可能计费。

每篇拥有单独任务与缓存。批次“部分完成”可重试，已完成文章不会重复生成，失败篇复用本次已完成的摘要、风格和搜索结果。想重新检索最新信息请新建任务或在稿件页重新生成。若符合条件的新文章不足 2–3 篇，会如实显示不足，不拿旧稿凑数。

旧配置中的 Qwen 自动替换为 OpenAI，旧 DeepSeek 配置保留；未完成任务重试也不再调用 Qwen，旧联网缓存将重新检索。建议创建新任务使用完整新版配置。阅读量缺失的文章不参与排名；最低阅读量默认 0，可在设置修改。

## 清理与检索（v0.6.0）

- 文章资料库：Ctrl/Shift 多选或全选当前列表后清理，也可一键清空整个资料库。清理正文、摘要和相关缓存，保留已生成稿件及其报告。
- 稿件工作台：可按标题或正文关键词检索，每页 50 篇；单选打开编辑，Ctrl/Shift 多选清理，支持全选本页和一键清空全部稿件。稿件清理同时清除正文、素材报告与历史版本，保留文章资料库。
- 清空全部始终涵盖搜索结果之外的记录，确认框会显示范围与数量。正在运行任务时禁止清理。
- 清理无法在界面撤销，需要留档时先导出或备份。数据库保留最小标识及清理记录，防止同一素材自动回流或原任务再次生成；已清理素材不能用于重新生成，现有稿件仍可编辑导出。SQLite 文件体积不保证即时缩小。

## 数据与密钥

- 数据文件：`%LOCALAPPDATA%\WeWriter\workspace.sqlite`。
- API Key：同目录 `keys.dpapi.json`，由 Windows DPAPI 加密，仅原 Windows 用户可解密。普通数据库中没有密钥。
- 原文、摘要、稿件与历史版本保存在本地；原文发送至摘要模型，摘要及证据片段发送至写作模型。API 服务有各自的数据处理政策。
- 原文图片保存在数据目录的 `article-images` 文件夹。正文不足 100 字的图片型文章默认跳过，由下一篇热门文章补位；在“设置 → 采集与写作”勾选“识别图片型文章”后，才会均匀选择最多 8 张压缩图片发送给 OpenAI 识别并缓存转写结果（额外 API 调用）。其他文章的图片不发送给模型。SQLite 备份不包含图片文件；恢复备份后可在文章资料库多选文章并执行“补采所选图片”。
- 设置页提供备份、恢复和打开数据目录。备份不包含 API Key；换电脑后重新配置密钥。
- 恢复前自动备份现有数据库，恢复后默认关闭定时，避免意外执行。
- 删除公众号只删除关注配置，保留文章和稿件。

## 定时与失败处理

- 关机、退出软件、休眠期间无法执行。恢复运行后合并补执行最近一次遗漏任务；采集范围仍按配置小时数计算，不承诺补齐长期离线期间的全部文章。
- 同一天定时任务只创建一次，失败需要手动重试，不会不断重复扣费。
- 重试沿用原配置和采集时间窗，复用已经获取的正文与逐段摘要。若需要使用新设置，重新运行新任务。
- 本版仅针对 HTTP 429 做有限重试。超时和其他服务器错误不自动重发，避免不确定的重复计费。
- 任务期间可以停止；正在进行的请求通常需等待返回，联网搜索请求超时为 300 秒，其他接口为 100 秒。

联网搜索发生连接失败或超过 300 秒时，该篇自动降级为仅基于公众号原文生成，并在任务警告、稿件审核提示和素材报告中标明“未使用联网资料”。API Key 无效、余额不足、权限错误或响应格式异常不会降级，以免掩盖配置问题。

## 采集范围与审核

微信读书模式：使用官方 Skill 检查书架，再优先分页获取历史文章列表，按真实发布时间和阅读量筛选并提取正文。登录状态和 Skill Key 均由 Windows DPAPI 加密保存，备份不包含凭据。历史列表临时返回 `-2041` 时，程序会通过官方 Skill 获取每个公众号的最新文章、真实发布时间、阅读量和点赞数继续运行，并在任务中记录降级提示；该次候选范围会缩小为每个公众号一篇，不会把采集时间伪装成发布时间。

若出现 `-2010` 或 `-2012`，在“公众号管理”重新执行 Edge 扫码登录。若出现 `-2041`，先确认设置页已经保存微信读书 Skill Key；新版会自动使用官方 Skill 降级，无需清空数据库。Skill Key 无效会明确提示重新配置。当前部分手机微信读书版本没有“设备管理”，无需寻找该入口。Edge 会在后台参与历史列表和正文采集，用于刷新临时验证凭据。

文章采集固定使用微信读书；旧 EveryInfra 采集配置自动迁移为微信读书。EveryInfra 仅用于评论获取。当前只在软件中移除公众号，不会取消手机端关注；再次同步书架会重新导入。

- URL 去重与相同正文去重；写过的文章不自动重复使用，可在稿件页“重新生成”显式复用原素材。
- 模型引用必须能在原文找到，正文来源标记必须属于输入来源。这是结构与引用检查，不能证明事实正确或文章原创性，稿件仍需人工审核。
- 导出支持 Markdown / TXT。尚不包括自动发布、邮件推送、Word 导出或多用户共享。

## 评论分析

默认启用：每篇入选文章通过 EveryInfra `article_comments` 获取最多 30 条可见评论，可在设置关闭或调整为 1–260 条。仅保留评论文本、样本编号、点赞数和时间，不保留作者昵称和头像。摘要模型提炼关注点、疑问和争议，校验引用编号；写作将其用于解释角度，不能当成事实或总体民意。

评论获取或分析失败会记录警告，仍可完成正文写作；空列表仅表示接口没有返回可见评论。原始评论与分析在本地缓存，成功步骤重试时复用。素材报告可查看评论分析及联网来源，来源 URL 可点击打开。清理文章资料库同时清除该文章的评论缓存。

版本验证：OpenAI 响应解析、搜索引用、旧配置迁移和评论校验已用模拟响应测试；真实 OpenAI 调用需先在设置保存 Key。

## 允许重新采集（v0.6.1）

设置 → 采集与逐篇写作 → 勾选“允许重新采集已清理文章” → 保存全部设置 → 概览“立即采集并生成”。默认关闭；只对使用新设置的新任务生效。已清理文章仍受时间范围、阅读量排名和单次篇数限制，入选后重新获取正文并用于生成，即使以前曾生成过稿件。原有稿件不受影响。重新获取完成的文章恢复正常去重，后续任务不会一直重复生成；旧任务重试仍沿用旧配置。

版本 v0.9.5：修复“分别生成多篇”时采集任务与写作子任务共用 Edge 配置目录导致的启动冲突。每个采集会话现在使用独立临时目录并在结束后自动清理，刷新后的登录 Cookie 仍会保存到本地加密凭据中。

版本 v0.9.4：采集、同步公众号、测试公众号和正文补采统一通过本机 Edge 会话访问微信读书，让网页自动刷新公众号接口的临时验证凭证。已保存的登录 Cookie 会安全注入独立浏览器会话；遇到 -2041 时通常无需清理数据库，只有网页会话本身失效才需要重新扫码。

版本 v0.10.1：稳定性更新。
- Edge 采集窗口：关闭时通过 CDP 让 Edge 真正退出并结束整个进程树；临时配置目录等待文件锁释放后再删除，启动时自动清理残留目录。同一次任务复用一个微信读书页面读取正文，不再每篇重新加载首页。
- 微信读书 `-2041`（临时验证凭据失效）或正文请求非 200 时，先自动重新加载页面/续期凭据并重试一次，仍失败才提示重新扫码。
- 诊断日志：数据目录 `logs\wewriter.log`（自动轮转，不记录密钥、Cookie 和正文）。程序异常会记录完整堆栈，界面提示错误类型与日志位置。
- 运行记录新增“错误类型”列，详情页给出处理建议；任务失败原因以结构化错误码保存（`jobs.error_code`），补位判断不再依赖报错文字。
- 稿件未通过来源标记或 JSON 格式校验时，自动带着错误原因重写一次（最多多一次写作调用）。
- 单篇文章出现意外异常时只记该篇失败，批次继续处理其余文章；单独重试某篇后，所属批次状态自动更新。
- 连接阶段失败（DNS、连接被拒）及 HTTP 502/503 自动有限重试；超时、500、504 仍不重发，避免重复计费。
- 文章列表中个别条目缺少标识或发布时间时跳过该条，不再导致整个公众号采集失败。
- 选文时默认跳过标题含促销/直播关键词（双11、直播间、抽奖、爆品等，可在设置中修改或关闭）的文章。
- 模型 Key 缺失时在采集前即报错，不再先采集、摘要后才失败。任务运行中选择退出，当前请求结束后自动退出。
- 内部结构：任务流程拆分为采集、素材、风格、评论、联网、写作、报告等独立步骤，各自缓存。

版本 v0.10.2：接入微信读书官方 Skill Key。书架同步改用官方 Skill 鉴权；历史文章列表出现 `-2041` 时，自动获取各公众号最新文章及其真实发布时间、阅读量和点赞数继续筛选。正文临时凭据失效时直接读取公众号原文。Edge 扫码登录不再因文章列表接口短暂失效而判定登录失败；设置页可保存和清除 Skill Key，并在任务中明确标出降级采集。
