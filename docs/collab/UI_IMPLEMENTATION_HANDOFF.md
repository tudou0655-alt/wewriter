## 3. 工作台

- 新任务：文章时间范围（今天、近 24 小时、近 3 天）、生成篇数 **整数 1—5**、启用公众号数量、热度优先、开始任务。今天以中国自然日计算；近 N 小时为滚动窗口。
- 1—5 需贯穿配置校验、保存、引擎批量生成、恢复和测试，不只是改下拉框。当前 `config.validate()` 仅允许 2/3，必须修正；拒绝 0、6、布尔值与非整数。
- 当前任务：阶段、数量、耗时、停止、查看详情；阶段线流光，点击查看阶段实况。沿用既有候选补位与热度逻辑，不借此改写生成链；不足时如实说明，不把目标数量当成已合格交付。
- 本次稿件：每篇状态与查看入口，单篇完成即可查看。生成完成、人工待审、通过必须分开；只有人工通过才计入合格稿件。
- 历史任务入口与当前任务并列，默认折叠，最近 10 条；更多通过分页访问。仅列时间、任务状态、合格篇数/目标及详情。详情保留采集漏斗、跳过原因、最近返回文章时间、诊断、继续原任务/重新采集的明确区别。
- 同时执行一个批次；已有任务时新建明确为“加入队列”，显示排队数、允许取消未开始任务。提交期间禁用重复点击，禁止静默覆盖正在运行任务。排队时冻结配置快照；已有定时任务与手动任务共享执行约束。重启沿用可解释的恢复状态，不自动重复计费；如现有存储不足见迁移批准边界。
- 停止前确认，保留稿件；已发请求不能承诺立即取消。不要自动清空历史任务或稿件；归档/清理策略本轮不自动新增破坏性动作。

## 4. 公众号管理

- 顶部主操作“扫码同步书架”，辅助“手动添加”；搜索已添加账号，逐个启用/停用，详情内删除并确认。修改采集名单从新任务生效，不破坏当前配置快照。
- 扫码使用现有微信读书登录与书架同步。范围明确为 **微信读书书架里的公众号**，`/web/shelf/sync` 中 `MP_WXS_` 条目；不是微信关注列表。不要移除这条功能或因删除 Skill Key 而误删登录态。
- 同步流程：登录/已登录 → 读取书架 → 展示可选列表 → 全选/勾选 → 导入；按稳定账号 ID 去重，不按名称猜测。已有账号保留启停状态；取消或失败保留原列表。过期二维码可刷新、会话可取消；接口失败不能一概要求重新扫码。
- 手动添加沿用已有标识/链接解析与校验，可搜索候选时让用户确认真实账号；原型“仅输入名字即入库”不作为正式匹配契约。
- 列表保留名称、采集状态、启停、详情。详情有本次可核实的最近返回文章时间和失败原因，不把它标成全网最近发文。
- 删除只移出后续采集名单，已有文章和稿件保留，不能产生关联数据误删。

## 5. 文章库

- 搜索标题、公众号筛选、发布时间范围、阅读量/点赞量/发布时间排序；默认阅读量优先。排序与过滤使用真实数值，不按格式化字符串排序。
- 列表：标题、公众号、发布时间、阅读、赞、使用/正文状态、查看文章。
- 未知与有效 0 区分，未知排在有效指标后；分页前先对整体结果排序。已有单项指标时间及保留策略不回退。
- 查看正文与图片，保留安全打开真实原文的入口；采集来源、时间、覆盖范围、指标来源与失败原因折叠在详情。保留原引用对应关系，不把采集接口名当事实来源。
- 不在本轮增加新采集服务或把此页变成复杂分析报表。

## 6. 稿件库

- 搜索标题、待审核/需修改/已通过筛选；默认最新稿件在前。列表展示标题、时间、状态，必要警告简短提示，查看入口进入稿件详情。
- 查看/编辑标题和正文、保存、取消、返回；未保存离开须提示，禁止静默丢失。保留现有版本记录。编辑已通过稿件后回到待审核。
- 标记需修改、审核通过需明确确认；真实保存状态并在首页合格数量反映。审核通过不等于发布，不能自动发布。
- 原型确认通过会清空提示只是演示：正式实现保留原始机器审核提示和人工处理记录，不得抹掉审计证据。可显示“人工已确认”，不能假称机器重新通过。
- 导出 Word(.docx)/Markdown(.md)，用户选择保存位置；发布稿保持干净，不插入内部 S/W 编号及审核过程。素材报告单独保留来源对应关系和审核记录。导出失败/用户取消不能显示成功；未审核稿导出应明确提示未通过。
- 来源与审核提示折叠；事实风险在列表/正文附近保留简短提醒。只有可信的真实引用才生成外链。
